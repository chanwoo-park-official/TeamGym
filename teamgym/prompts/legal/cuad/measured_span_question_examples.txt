Use these examples as decision-design style guidance. Do not copy the facts
unless the supplied CUAD spans actually support them.

Bad 2-span option design:
{
  "decision_set": [
    {"value": "distribution_only", "definition": "A distribution right is granted."},
    {"value": "name_use_only", "definition": "A name-use right is granted."},
    {"value": "distribution_plus_name_use", "definition": "A distribution right and a name-use right are granted."}
  ],
  "why_bad": "The answer is visually obvious because it is the only combined option and the value name exposes A+B."
}

Good 3-span legal profiles:
- rule + condition + consequence
- right holder + exercise deadline + fallback consequence
- monetary cap + damages exclusion + carveout
- obligation threshold + measurement period + shortfall remedy
- license grant + permitted scope + restriction or exception

Good 4-span legal profiles:
- base obligation + scope + measurement condition + shortfall remedy
- audit holder + record scope + timing/frequency condition + cost/reimbursement rule
- liability cap + remedy limit + damages exclusion + exception/carveout
- license grant + covered asset + permitted channel/territory + restriction/condition
- election right + trigger/scope + exercise deadline + fallback consequence

General k-component profile design:
- Hidden construction may use k components, where k is the number of selected spans needed for the answer.
- Public option values must stay neutral: decision_a, decision_b, decision_c, decision_d, decision_e, decision_f.
- Public definitions should be natural legal-profile sentences, not component formulas.
- Wrong profiles should change one or two components while keeping the same overall complexity.
- Option count may vary from 2 to 6. Prefer 3, 4, 5, or 6 options when plausible; do not always return exactly four options.
- If there are 5 or 6 options, keep all value names parallel and all definitions similarly detailed.

Final check before returning JSON:
- If option values reveal component counts, replace them with decision_a/decision_b/decision_c/decision_d.
- If one definition is much longer or more specific than all others, rebalance definitions.
- If a single span can determine the oracle answer, revise the question or choose a different answer profile.
- If evidence contains a conditional or exception phrase, the answer definition must preserve that condition.
- Avoid literal "A+B+C" wording in user-facing option values. In definitions, write complete legal-profile sentences rather than formula labels.
